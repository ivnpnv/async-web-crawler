# Измерение производительности

Измерения выполнены на Windows с Python 3.12. Один проход для каждого размера.
Сервер и клиенты работают на одной машине. Сервер добавляет задержку 0.01 с,
фактическая длительность ожиданий зависит от планировщика Windows.

Оба клиента используют keep-alive и один HTMLParser. Последовательный клиент
выполняет блокирующие HTTP-запросы в рабочем потоке, чтобы локальный сервер
продолжал работать. Асинхронный клиент использует 20 работников и 20 мест на хост.
Сохранение отключено, robots.txt отключён только для этого локального сравнения,
rate_limit установлен в 1000000 для исключения его влияния.

| Страницы | Последовательно, с | Асинхронно, с | Ускорение | Пик Python sync, МиБ | Пик Python async, МиБ |
| --- | --- | --- | --- | --- | --- |
| 100 | 1.8332 | 0.4200 | 4.36 | 0.677 | 3.509 |
| 500 | 9.0148 | 2.0719 | 4.35 | 1.160 | 4.624 |
| 1000 | 18.0091 | 4.2177 | 4.27 | 2.028 | 5.763 |

Машиночитаемый результат последнего запуска находится в results/benchmark.json.
Память измеряется tracemalloc, включая выделения Python локального сервера.
Это не RSS и не полная память нативного парсера lxml. Само трассирование влияет
на время. Сравнение измеряет совокупность HTTP-загрузки и парсинга. Async-клиент
также создаёт метаданные и состояния обхода, поэтому удерживает больше памяти.

## Найденные узкие места

В установленном Python 3.12 Windows time.monotonic() использует GetTickCount64
с разрешением 0.015625 с. Из-за этого ограничитель не мог выдавать частые
разрешения даже при очень высоком rate_limit. Для коротких интервалов выбраны
монотонные часы perf_counter() с разрешением 0.0000001 с в этом окружении.
Проверка поведения добавлена в тесты.

До этой замены замер 1000 страниц давал 17.0424 с последовательно и 15.7129 с
асинхронно. Изменение не отменяет лимиты вежливости и Crawl-delay.

Создание задачи для каждого URL уровня заменено ограниченным числом работников.
Поэтому число клиентских задач зависит от max_concurrent. Результаты и найденные
URL продолжают храниться в памяти и растут с числом страниц.

## Повторение

```powershell
.\.venv\Scripts\python.exe -m src.benchmark --sizes 100 500 1000 --delay 0.01 --concurrency 20 --output results/benchmark.json
```

Один локальный проход показывает поведение этой нагрузки. Время реального сайта
зависит от его задержек, rate_limit, размеров страниц, ошибок и хранилища.
Файловое сохранение с заменой целого файла может стать главным ограничением.
